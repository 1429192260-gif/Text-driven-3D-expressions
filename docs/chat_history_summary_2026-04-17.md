# 项目聊天纪要（2026-04-17）

## 1. 当前项目主题

本项目的核心任务是构建一个中文 `text-only` 驱动的三维表情生成原型系统，整体链路为：

`中文文本 -> 情绪类别/强度前端 -> 表情参数预测后端 -> 3D表情生成/可视化`

当前阶段的工作重点不是完整产品，而是先完成一个可用于小论文的基础实验体系，并验证该任务在中文场景下的可行性与改进空间。

## 2. 当前已经完成的主要内容

### 2.1 后端表达预测主线

已经完成多个后端方法的训练与比较，包括：

- `Baseline MLP`
- `Semantic MLP`
- `Prior Only`
- `Prior-Fusion`

在 `804 source_holdout` 主实验中，`Prior-Fusion` 表现最好，说明在表情参数预测时引入情绪先验信息是有效的，能够明显优于纯 MLP 回归。

### 2.2 text-only 前端主线

前端经历了从“自训练小模型”到“预训练中文情绪模型 + 规则增强”的逐步改进：

1. 最初版本为基于人工小规模数据训练的 `learned front-end`
2. 后续接入本地 `Chinese-Emotion-Small`
3. 在其上进一步加入类别映射、强度校准、中文关键词规则和弱情绪修正，形成 `rules_v4`

### 2.3 微博真实数据扩展

已经使用微博文本进行数据扩展和跨域验证，完成了：

- `weibo train -> manual 5-class test`
- `weibo train -> manual 8-class test`

结果表明，即使训练数据来自真实微博文本，`Prior-Fusion` 仍然在手工测试集上保持最优，说明方法具备一定的跨域泛化能力。

### 2.4 深入分析实验

已经补充完成两类更有论文价值的分析实验：

- 案例分析实验
- 按情绪类别拆分误差分析

这两部分的意义在于：不再只停留在总 MAE，而是能够具体分析哪些类别改进明显、哪些样本仍然困难，从而提升论文实验的解释力。

## 3. 当前最关键的实验结论

### 3.1 后端主线结论

在多个后端方案中，`Prior-Fusion` 是当前最优主线，说明“将情绪先验与语义特征融合后再做表情参数预测”是合理路线。

### 3.2 text-only 前端严格消融结论

在统一后端 checkpoint 和统一测试集条件下，严格消融结果如下：

- `learned`: `MAE = 0.085059`
- `hf_raw`: `MAE = 0.065244`
- `hf_rules_v4`: `MAE = 0.017869`

结论：

- 使用预训练中文情绪模型前端，比我们最初的小规模自训练前端明显更强
- 改进并不只是“换了一个更强模型”
- 真正的主要提升来自“规则增强 + 任务适配”

### 3.3 案例分析结论

在按 8 类抽取代表样本后，三种前端的平均案例参数误差为：

- `learned = 0.067369`
- `hf_raw = 0.074353`
- `hf_rules_v4 = 0.019119`

说明 `hf_rules_v4` 不仅在整体 MAE 上更优，在具体样本层面也能更稳定地逼近目标表情参数。

### 3.4 按情绪类别拆分误差分析结论

按 8 类拆分后发现：

- `hf_rules_v4` 在大多数类别上都优于 `learned` 和 `hf_raw`
- 提升最明显的类别集中在：
  - `disgust`
  - `concern`
  - `bored`
- 当前仍然较难的类别主要是：
  - `surprise`
  - `angry`

这说明规则增强对细粒度、弱情绪和边界情绪尤其有效，但某些高混淆类别仍然存在改进空间。

## 4. 三次前端改进的具体内容

### 4.1 第一次改进：替换前端模型

将原来基于小规模人工数据训练的前端分类器，替换成本地部署的 `Chinese-Emotion-Small`，直接输出情绪类别与置信分数。

基本实现方式：

```text
p = softmax(Model(x))
label_id = argmax(p)
confidence = max(p)
```

目标是验证：现成中文情绪模型是否优于我们原始的小规模自训练前端。

### 4.2 第二次改进：标签映射与强度校准

由于原模型的标签体系与我们的 8 类表情任务不完全一致，因此建立了人工映射表，将模型标签对齐到：

`happy, sad, angry, surprise, disgust, concern, bored, calm`

例如：

```text
question -> concern
```

同时，强度并不是直接使用模型置信度，而是设置基础强度，再结合文本特征做修正：

```text
intensity_raw = base_raw(emotion)
              + 程度词增强
              - 弱化词抑制
              + 标点修正
```

### 4.3 第三次改进：中文规则增强（rules_v4）

在模型输出后加入规则后处理层，主要包括：

- 情绪关键词表
- 程度副词表
- 弱情绪词表
- 缓和表达词表
- 感叹号/问号修正
- 特定类别定向补偿

具体实现方式为：

1. 对每个情绪类别维护一组关键词及权重
2. 若文本命中对应关键词，则累计该类别得分
3. 将模型原始预测也作为一个弱投票加入
4. 若某一类别得分超过阈值，则覆盖原模型结果
5. 根据关键词命中数、程度副词、弱化词、语气词等重新估计强度

可概括为：

```text
score_e = 关键词匹配得分 + 原模型弱投票
emotion = argmax(score_e)
intensity = base + confidence修正 + keyword修正 + 语气修正
```

规则重点改善了 `concern / bored / disgust` 等原模型容易混淆的类别，也对“有点、还好、一般”等弱情绪表达做了抑制处理。

## 5. 当前项目的创新点

当前可以成立的创新点主要有以下几个：

### 5.1 任务层面的创新

不是做传统文本情绪分类，而是进一步把中文文本映射到可驱动的三维表情参数空间，即：

`text -> emotion/intensity -> expression parameters`

相比常规分类任务，更强调生成导向和可控表情建模。

### 5.2 方法层面的创新

没有直接把预训练中文情绪模型当黑盒使用，而是在其上增加：

- 标签体系对齐
- 强度重估
- 中文规则增强
- 弱情绪与边界情绪补偿

本质上属于“预训练情绪模型 + 中文任务适配”的轻量方案。

### 5.3 实验层面的创新

针对细粒度弱情绪类别进行了专项改进和分析，尤其关注：

- `concern`
- `bored`
- `disgust`

并通过案例分析和按类别拆分误差，证明改进不只是平均指标提升，而是确实改善了细粒度情绪表达。

## 6. 当前存在的不足

虽然目前已经形成完整实验闭环，但从论文角度看，仍存在以下不足：

### 6.1 文献阅读还不够系统

目前实验主要是边做边推进，已经有基础研究线，但与同门相比，系统性的文献阅读和复现还不够充分。

### 6.2 规则增强仍偏经验设计

`rules_v4` 有效果，但当前仍以人工经验规则为主，后续需要通过更细的消融和更严谨的表述来支撑其合理性。

### 6.3 可视化闭环还不完整

目前主要完成的是“参数预测实验”，还没有形成一个强展示力的 3D 表情可视化闭环。

### 6.4 论文级对比还可以继续补

当前对比已经有基础，但如果要进一步提升论文说服力，还可以加入：

- 更多前端对比
- 更严格的规则消融
- 更完整的跨域与弱情绪专项实验

## 7. 对当前项目阶段的判断

目前项目不是“做得不够”，而是已经完成了第一阶段：

`任务跑通 + 基础实验闭环 + 初步创新点形成`

但尚未进入第二阶段：

`论文级打磨 + 系统文献支撑 + 更严谨的实验矩阵 + 可视化展示`

因此当前最合理的判断是：

项目已经具备基础论文雏形，但还需要进一步补强，才能达到更扎实的研究工作标准。
